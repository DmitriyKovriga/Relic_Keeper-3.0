# Warrior movement animation refresh

Warrior now uses new sprites under `Heroes/WarriorResources/Refined`. The original run, jump, fall sheets and portrait remain available. Character ID, starting stats, movement physics, equipment and passive tree are unchanged.

- Run: nine poses with calmer grounded steps, lower knee lift and a one-pixel upper-body/hand settle on alternate contacts. The upper body and hands settle together by at most one native pixel. Held items follow exactly the same frame offset. No isolated hand cutouts or erased rectangles. The calmer cycle lasts 0.72 seconds; gameplay movement speed is unchanged. The first pose supplies the resting pose.
- Jump/fall: current frames are a complete AI-generated PixelLab cycle, with intact generated forearms and hands. Arms remain down beside the body; leg poses progress from takeoff through the shared apex into descent. No torso/hand rectangle copying or contour trimming is applied to the accepted frames. Airborne runtime scale stays (1,1). Narrowing is subtler than the previous hand-edited silhouette; preserve natural anatomy rather than force a fixed pixel width.
- Jump uses source frames 0-4 and holds the apex. Fall repeats source pose 4 throughout descent, so the legs do not walk back toward the standing pose while airborne. Landing recovery supplies the return to ground stance. Both clips share the identical apex. A jump that starts while the animation is in Jump/Fall restarts at authored frame 3, with its matching weapon offsets; ground jumps start at frame 0. AirborneRestartFrame defaults to 0 for existing character data and is clamped to the loaded clip bounds. Every jump event restarts the clip, including a completed ascent.
- Landing: an optional CharacterData animation triggered by PlayerMovement.OnLanded after jumping/falling. Five poses compress to 116% width / 85% height, rebound to 97% width / 103% height and settle over 0.30 seconds. It overrides idle/run sprite selection during recovery but does not block movement, attacks or a new jump. Spawn/duplicate contacts do not replay it. Characters without landing data retain their existing behavior.
- Every sprite keeps a 28 x 28 FullRect canvas, centred pivot, 24 PPU, point filtering and uncompressed alpha. Uniform frame bounds retain the existing foot-alignment and weapon-socket behavior.
- Warrior run weapon offsets are 0 or -1/24 unit and follow the sprite frame without interpolation, keeping equipment aligned with the subtly moving grip. The optional weapon-offset system remains available for other animations. The bowstring remains unchanged.

`Tools > Visuals > Apply Refined Warrior Movement` reapplies imports and CharacterData bindings. `WarriorMovementVisualBuilder.AssembleGeneratedFrames` packs accepted individual frames from `%LOCALAPPDATA%/Temp/codex-warrior-refresh` using Unity's image decoder/encoder before applying them. It does not require runtime network access.

The run builder imports the accepted PixelLab native FixedGripRun-sheet.png. Jump/fall use authored airborne frames and unit PresentationScales, suppressing the legacy jump pulse. Landing uses the first complete run sprite with a small compression and rebound. Earlier handless sheets are not used.
