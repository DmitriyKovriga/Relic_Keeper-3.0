# Visual Production Roadmap

Рабочая дорожная карта по поэтапному улучшению визуальной подачи `Relic Keeper`.

Цель дорожной карты:
- убрать ощущение "flash/сырой демки";
- сделать бой живым и читаемым;
- придать сценам глубину и атмосферу;
- выстроить production-ready правила, чтобы новый контент сразу попадал в нужный визуальный уровень.

Принципы маршрута:
- сначала правим то, что дает максимальный визуальный прирост за минимальную цену;
- не начинаем с тотального redraw всего проекта;
- сначала собираем presentation system, потом масштабируем арт;
- каждая фаза должна давать заметный прирост сама по себе.

---

## Phase 0. Baseline And Visual Rules

Цель: зафиксировать единые правила качества до массовой доработки сцены, FX и UI.

- [ ] Утвердить целевой визуальный столп проекта в 3 фразах.
- [ ] Зафиксировать 1 главный референс по атмосфере сцены.
- [ ] Зафиксировать 1 главный референс по боевой кинетике.
- [ ] Зафиксировать 1 главный референс по глубине и layering.
- [ ] Описать, каким должен читаться кадр: игрок, опасность, интерактив, фон.
- [ ] Утвердить палитровый принцип текущего biome: базовый тон, теплые акценты, холодные акценты.
- [ ] Утвердить правило по пустотам экрана: сколько "воздуха" допустимо сверху, снизу и по краям.
- [ ] Утвердить базовый PPU и правила pixel-perfect привязки для всех визуальных якорей.
- [ ] Утвердить правило: каждая боевая сущность обязана иметь grounding-слой.
- [ ] Утвердить правило: каждая боевая механика обязана иметь presentation chain.
- [ ] Создать короткий visual checklist для новых врагов.
- [ ] Создать короткий visual checklist для новых комнат.

Готовность фазы:
- есть короткий документ правил;
- команде понятно, что считается "готово хорошо", а что "еще сыро".

## Phase 1. Fast Anti-Flatness Pass

Цель: быстро убрать ощущение плоской и дешевой картинки без полного redraw окружения.

### Grounding
- [ ] Добавить контактную тень под игроком.
- [ ] Добавить контактную тень под всеми обычными врагами.
- [ ] Добавить усиленную контактную тень под крупными врагами.
- [ ] Добавить тени под подвесными и нависающими платформами.
- [ ] Проверить, что тени не ломают pixel-perfect и не дают грязное мерцание.

### Dust And Surface Reaction
- [ ] Добавить dust puff при беге игрока.
- [ ] Добавить dust puff при приземлении игрока.
- [ ] Добавить dust puff при рывке/додже.
- [ ] Добавить тяжелый ground impact для массивных врагов.
- [ ] Добавить легкую surface reaction при остановке на скорости.

### Hit Readability
- [ ] Добавить базовый hit spark для melee-попаданий.
- [ ] Добавить базовый blood burst для живых целей.
- [ ] Добавить отдельный dry impact для брони/кости/каменных целей.
- [ ] Добавить короткий residual effect после удара, чтобы импакт не исчезал мгновенно.

### Screen Cleanup
- [ ] Ослабить пустую однотонную массу в верхней части кадра.
- [ ] Ослабить пустую однотонную массу в нижней части кадра.
- [ ] Проверить, что бой визуально остается главным событием на экране.

Готовность фазы:
- персонажи и враги перестают выглядеть "наклейками";
- уже на старом окружении бой выглядит заметно дороже.

## Phase 2. Combat Presentation System

Цель: сделать действия в бою ощутимыми, тяжелыми и живыми.

### General Combat Rules
- [ ] Зафиксировать стандарт presentation chain: anticipation -> motion -> impact -> residue.
- [ ] Зафиксировать отдельные шаблоны для light hit, heavy hit, dash, projectile, cast.
- [ ] Сделать таблицу типов поверхностей: flesh, bone, armor, stone, magic.

### Melee
- [ ] Добавить trail/slash read для рубящих атак.
- [ ] Добавить отдельный impact burst для сильных melee-ударов.
- [ ] Усилить ощущение массы у heavy enemy attacks.
- [ ] Сделать урон читаемым не только цифрами, но и картинкой.

### Dodge / Mobility
- [ ] Привести dodge VFX к единому качественному уровню.
- [ ] Добавить стартовый visual burst на начале dodge.
- [ ] Добавить clean exit residue на окончании dodge.
- [ ] Проверить, что шлейфы и afterimages не превращают экран в шум.

### Projectiles And Magic
- [ ] Для каждого снаряда ввести ядро, хвост, след и исчезновение.
- [ ] Добавить impact state у projectile hit.
- [ ] Развести визуально магические школы по цвету и энергии.

### Enemy Telegraphing
- [ ] Усилить wind-up у опасных enemy attacks.
- [ ] Добавить ясный визуальный телеграф charge attacks.
- [ ] Проверить, что dangerous state врага читается даже без знания механики.

Готовность фазы:
- игрок чувствует вес и различие действий;
- бой "продает" игру даже на простом уровне.

---

## Phase 3. Camera And Framing Pass

Цель: сделать кадр более режиссированным и убрать ощущение случайного захвата сцены.

### Framing
- [ ] Проанализировать текущий gameplay кадр на типовых аренах.
- [ ] Уменьшить объем бесполезного воздуха сверху.
- [ ] Уменьшить объем бесполезного воздуха снизу.
- [ ] Проверить комфортную высоту игрового горизонта.
- [ ] Проверить, не слишком ли мелко игрок и враги читаются в кадре.

### Camera Behavior
- [ ] Подобрать более приятную follow-композицию.
- [ ] Проверить допустимость легкого look-ahead по движению.
- [ ] Проверить допустимость мягкого combat emphasis при рывках и сильных ударах.
- [ ] Убедиться, что камера не ломает пиксельную четкость и не создает subpixel noise.

### Combat Readability
- [ ] Проверить видимость дальних и ближних угроз на одном экране.
- [ ] Проверить, что HUD не перетягивает внимание у боевой зоны.

Готовность фазы:
- экран выглядит более собранным;
- центр внимания естественно уходит в боевую зону.

---

## Phase 4. Scene Depth Pass

Цель: убрать ощущение плоской декорации и превратить комнату в пространство.

### Background Layering
- [ ] Ввести дальний фоновый слой.
- [ ] Ввести средний архитектурный слой.
- [ ] Отделить gameplay layer по контрасту от задника.
- [ ] Добавить foreground layer для редких элементов перед камерой.

### Architecture
- [ ] Добавить дальние арки/ниши/проемы.
- [ ] Добавить вторичную стену или каркас за основной стеной.
- [ ] Добавить колонны, балки, подпорки, решетки, цепи.
- [ ] Убрать ощущение, что платформы просто висят в воздухе.

### Surface Variety
- [ ] Добавить вариации тайлов пола.
- [ ] Добавить вариации тайлов стены.
- [ ] Добавить вариации платформ.
- [ ] Добавить small damage marks, cracks, dirt clusters.

Готовность фазы:
- сцена ощущается местом, а не плоской картинкой.

---

## Phase 5. Lighting And Atmosphere

Цель: придать сцене настроение, тональную иерархию и художественный объем.

### Lighting Model
- [ ] Утвердить базовую схему света для dungeon biome.
- [ ] Выбрать основные теплые источники света.
- [ ] Выбрать основные холодные тени/контрсвет.
- [ ] Утвердить, где должны быть локальные яркие акценты, а где провалы в темноту.

### Practical Implementation
- [ ] Добавить локальные световые пятна в ключевых участках сцен.
- [ ] Добавить мягкую тональную градацию по глубине.
- [ ] Добавить свечение вокруг магических и опасных объектов.
- [ ] Добавить ambient particles: dust motes, faint smoke, embers, spores или аналог по биому.

### Readability Safety
- [ ] Проверить, что игрок не теряется в темных участках.
- [ ] Проверить, что враги остаются читаемыми на фоне новых световых схем.
- [ ] Проверить, что lighting не превращает pixel art в грязь.

Готовность фазы:
- сцена становится атмосферной;
- кадр получает художественную глубину без потери читаемости.

---

## Phase 6. Environment Art Pass

Цель: поднять потолок качества мира после того, как presentation-основа уже работает.

### Tileset Quality
- [ ] Пересобрать стену как более богатую по форме и истории поверхность.
- [ ] Пересобрать пол как более живую и менее однообразную поверхность.
- [ ] Пересобрать платформы так, чтобы они выглядели частью архитектуры.
- [ ] Сделать набор вариаций для краев, углов, переходов и damaged states.

### Props
- [ ] Собрать библиотеку props для dungeon-сцен.
- [ ] Добавить props для дальнего фона.
- [ ] Добавить props для среднего плана.
- [ ] Добавить редкие foreground props.
- [ ] Убедиться, что props не мешают геймплею и silhouette readability.

### Storytelling
- [ ] Добавить следы жизни/разрушения/опасности в окружение.
- [ ] Добавить элементы, которые объясняют характер локации.
- [ ] Ввести логические группы декора, а не случайный шум.

Готовность фазы:
- окружение выглядит как авторский мир, а не тестовый room blockout.

---

## Phase 7. UI Integration Pass

Цель: сделать UI частью общей художественной подачи, а не отдельным тяжелым слоем.

### HUD Structure
- [ ] Пересмотреть вес верхнего skill HUD.
- [ ] Пересмотреть вес нижнего resource HUD.
- [ ] Проверить, что UI не давит на игровое поле.
- [ ] Убрать лишние массивные темные/пустые блоки.

### Combat UI
- [ ] Привести enemy HP bars к единой более аккуратной системе.
- [ ] Привести combat numbers, bars, flashes и state indicators к одному визуальному языку.
- [ ] Проверить, что UI не спорит по контрасту с боевыми FX.

### Atmosphere Fit
- [ ] Синхронизировать визуальную плотность UI и мира.
- [ ] Проверить, что интерфейс не выглядит "дороже" самой сцены.

Готовность фазы:
- экран читается как единое целое: мир + бой + интерфейс.

---

## Phase 8. Animation Life Pass

Цель: убрать манекенность и добавить вторичную жизнь без полного redo персонажей.

### Player
- [ ] Добавить более живой idle.
- [ ] Добавить микро-реакцию на ускорение и торможение.
- [ ] Добавить secondary motion оружию и/или части силуэта.
- [ ] Проверить, что движение не выглядит "кукольно" при остановках и разворотах.

### Enemies
- [ ] Дать каждому классу врагов свою пластику even в idle.
- [ ] Добавить micro-motion опасным врагам.
- [ ] Проверить, что крупные враги ощущаются тяжелыми даже без атаки.

Готовность фазы:
- персонажи перестают быть статичными манекенами в паузах между действиями.

---

## Phase 9. Biome Scalability

Цель: чтобы визуальный уровень можно было поддерживать и масштабировать на будущий контент.

- [ ] Зафиксировать art bible по текущему dungeon biome.
- [ ] Сформировать список reusable visual modules.
- [ ] Вынести обязательные presentation-элементы в reusable prefabs/системы.
- [ ] Сделать шаблон для новой комнаты.
- [ ] Сделать шаблон для нового врага.
- [ ] Сделать шаблон для нового боевого VFX.
- [ ] Подготовить правила, какие слои и элементы обязаны быть в каждом biome.

Готовность фазы:
- новый контент собирается быстрее;
- качество не держится на памяти и интуиции.

---

## Phase 10. QA And Regression Checklist

Цель: закрепить качество и не сломать подачу по мере роста проекта.

- [ ] Проверить все боевые сцены на readability при высокой плотности врагов.
- [ ] Проверить игру без FX spam и с FX spam.
- [ ] Проверить все платформенные ситуации на визуальную читаемость.
- [ ] Проверить, что HUD хорошо работает на минимальном и большом разрешении.
- [ ] Проверить, что lighting не ломает важные silhouettes.
- [ ] Проверить, что контактные тени не конфликтуют с кровью, пылью и декором.
- [ ] Проверить, что новые visual layers не ломают sorting.
- [ ] Проверить производительность после всех presentation improvements.

Готовность фазы:
- качество стабильно;
- система не разваливается по мере роста контента.

## Recommended Execution Order

Оптимальная последовательность внедрения:

- [ ] Выполнить `Phase 0` полностью.
- [ ] Выполнить `Phase 1` полностью.
- [ ] Выполнить `Phase 2` полностью.
- [ ] Выполнить `Phase 3` полностью.
- [ ] Выполнить `Phase 4` полностью.
- [ ] Выполнить `Phase 5` полностью.
- [ ] Выполнить `Phase 7` полностью.
- [ ] Выполнить `Phase 6` полностью.
- [ ] Выполнить `Phase 8` полностью.
- [ ] Выполнить `Phase 9` полностью.
- [ ] Выполнить `Phase 10` полностью.

Причина такого порядка:
- сначала убираем дешевизну presentation-layer;
- потом делаем бой живым;
- затем собираем глубину и атмосферу;
- только после этого вкладываемся в тяжелый environment pass;
- в конце фиксируем правила масштабирования и regression safety.

## First Milestone

Первый milestone, после которого игра уже должна перестать выглядеть сырой:

- [ ] Контактные тени у игрока и врагов.
- [ ] Dust/landing/dash surface reactions.
- [ ] Базовые hit sparks и impact residue.
- [ ] Подтянутый gameplay framing.
- [ ] Второй фоновый слой и ослабление плоской массы.
- [ ] Первые локальные световые пятна.
- [ ] Облегчение и лучшая интеграция HUD.

Если этот milestone сделан хорошо, игра уже должна перейти из состояния "сырая демка" в состояние "есть лицо и направление".
