# Раскладка пассивного дерева

Этот скилл отвечает за **геометрию**: где кластеры, как идут дороги, где стоят ноды. Какой нод чем является (архетипы, статы, кейстоуны как правила) решает `relic-keeper-passive-tree`. Ноды после генерации пустые (`Template: {fileID: 0}`), их наполняют отдельно.

Эталон: дерево Rogue («сюрикен»), `scripts/rogue_shuriken.py`. Прочитай его целиком перед своей раскладкой. API и словарь кластеров: [reference.md](reference.md).

## Неизменное

- Старт `(1800, 1400)`. Скелет (координаты от старта, ось Y вниз): 4 диагональных луча с нодами на `(±120, ±120)`, `(±220, ±220)`, углы `(±360, ±360)`; углы по сторонам света `(0, ±500)`, `(±500, 0)`; прямые рёбра восьмиугольника между 8 углами.
- 8 кейстоунов снаружи углов: `(0, ±560)`, `(±560, 0)`, `(±400, ±400)`, каждый связан только со своим углом.
- `treegen.Tree` строит скелет сам и берёт ID скелета из существующего ассета по позиции. Скелет не двигать и его рёбра не удалять: валидатор это ловит. Первую ноду луча можно посадить на орбиту центрального кластера (`orbit(..., existing=q.L1)`), если позиция не меняется.

## Ориентиры по объёму (дерево воина)

~150 нод: ~110 малых, ~30 средних, 8 кейстоунов, ~15–20 кластеров. Кластер почти всегда кончается средней нодой. Дорога между кластерами — только малые ноды. До кейстоуна диагонали 4 хопа по скелету, это нормально.

## Процесс

```
- [ ] 1. Мотив класса → силуэт (таблица ниже). Не повторять силуэт уже готовых деревьев
- [ ] 2. Симметрия: C4 (вертушка), D4 (зеркало + поворот) или NONE
- [ ] 3. Карта областей сектора: какие области между лучами, рёбрами и центром, что в каждой
- [ ] 4. Скрипт раскладки: копия rogue_shuriken.py → scripts/<class>_<motif>.py
- [ ] 5. Превью: запустить → прочитать PNG (Read) → исправить → повторить
- [ ] 6. Валидатор пишет OK (не --force, если нет веской причины)
- [ ] 7. --write, `agents-unity-bridge refresh`, тест раскладки, консоль без ошибок
- [ ] 8. Новый класс: подключить ассет к герою и добавить тест (ниже)
- [ ] 9. Попросить у пользователя скриншот из редактора и поправить по нему
```

Запуск из корня проекта (нужен Pillow):

```powershell
python .cursor/skills/relic-keeper-tree-layout/scripts/<layout>.py           # превью + проверка
python .cursor/skills/relic-keeper-tree-layout/scripts/<layout>.py --label   # подписи нод на превью
python .cursor/skills/relic-keeper-tree-layout/scripts/<layout>.py --write   # запись ассета
python .cursor/skills/relic-keeper-tree-layout/scripts/render.py <tree.asset> <out.png>   # рендер любого дерева
```

Превью кладётся во временную папку, не в репозиторий. Рендер рисует так же, как игра: дуга по короткой стороне орбиты, хорда при ≥170° (красным), Безье по anchor + handles. Смотри на PNG после каждой правки. Прежде чем проектировать своё, отрендерь деревья воина и мага: `Assets/Resources/PassiveTrees/WariorPTree/WariorPassiveTree.asset`, `.../MagePassiveSkillTree/MagePassiveSkillTree.asset`.

Правку файла скрипта и его запуск не делай в одном параллельном батче: запуск может прочитать старую версию.

## Сектор и симметрия

Раскладка описывает **один сектор** в локальной рамке: северная четверть между лучами NW и NE, координаты от старта. Готовые имена скелета: `q.L1 q.L2 q.Lv` (левый луч), `q.R1 q.R2 q.Rv` (правый), `q.N` (угол сверху), `q.keyN`, `q.keyR`. Углы орбит: 0 = вправо, 90 = вниз, 270 = вверх.

- `C4`: сектор повторяется поворотом на 90°. Вертушка, форма закручена (рога).
- `D4`: сектор строит только половину `x ≥ 0`, вторую даёт зеркало. Ноды на оси `x = 0` создавай только при `not q.mirror`, а в зеркальной половине бери их через `q.at(...)`. Строгий, «гербовый» вид, как у воина.
- `NONE`: один вызов, всё дерево строится вручную. Для асимметричных классов (прокажённый).
- `q.variant = k % 2` чередует варианты кластеров между соседними четвертями, не ломая силуэт. Минимум два варианта на каждую область.

## Правила плавности (выстраданные)

1. **Круг — это орбита, не Безье.** Кольцо из отдельных кривых даёт изломы на каждой ноде. Нужен круг — ставь кластер с орбитой, ноды через `orbit`/`ring`.
2. **Длинная дуга — одна кривая.** `curve_chain` ставит ноды на одну кубическую Безье и режет её точно по нодам. Не собирай длинную линию из независимых сегментов.
3. **Путь через несколько нод — `spline`** (Catmull-Rom, C1). Концам задавай касательные: вдоль ребра восьмиугольника на старте, `q.tangent(angle)` на входе в орбиту. Тогда хвост продолжается дугой без излома.
4. **Вход в кластер — по радиусу или по касательной, никогда «сбоку».** Радиально: `angle = q.toward(cluster, node)`, тогда нод, вход и центр лежат на одной прямой. Касательно: `spline(..., t_end=q.tangent(entry))`.
5. **Шаг на орбите — не меньше ~46 единиц дуги** (`2·r·sin(Δ/2)`). Иначе ноды слипаются. Средняя рядом со средней — не меньше 50. Каждая дуга < 170°.
6. **Линия не проходит сквозь чужую ноду и не пересекает другую линию.** Валидатор проверяет оба пункта.
7. Прямые — для спиц, радиальных входов и рёбер восьмиугольника. Всё остальное — дуги орбит или Безье.

## Правила разнообразия

- Силуэт читается с расстояния: 2–3 крупные фигуры (лезвия, крылья, циферблат) плюс центр. Кластеры — детали внутри фигур.
- Центр вокруг старта не пустой: кольцо-орбита через первые ноды лучей, внутренняя орбита, спицы между лучами.
- В каждом дереве не меньше 5 разных типов кластеров из словаря в reference.md. Два соседних одинаковых кластера — только если это часть силуэта.
- Не копируй силуэт другого класса. Воин — строгий D4 со стрелками; маг — завитки-«S»; рога — сюрикен C4.

## Мотивы классов

Стартовые идеи. Уточни у пользователя, если он видит класс иначе.

| Класс | Силуэт | Симметрия | Характерные кластеры |
|---|---|---|---|
| Вампир | Крылья летучей мыши от центра к диагоналям; клыки к северу и югу | D4 или зеркало по вертикали (NONE) | «Капля» (кольцо со средней внизу), зубчатые дуги по краю крыла |
| Шаман | Спирали-вихри, тотем по вертикальной оси | C4 с сильной закруткой | Концентрические орбиты, спираль с переходом между орбитами |
| Дуэлянт | Две скрещённые рапиры: длинные прямые клинки по диагоналям, гарды-дуги | D4 | Гарда (полукруг поперёк спицы), «восьмёрка» из двух касающихся кругов |
| Рыцарь | Щит и крест: жёсткие прямые, мало кривизны | D4 | Квадратные рамки из дуг 90°, двойной мост |
| Паладин | Солнце: лучи от центрального кольца, ореол | D4 | Большая центральная орбита с 8 выходами, лучевые цепочки к краю |
| Прокажённый | Асимметрия, «наросты», рваные контуры | NONE | Кластеры разного радиуса гроздьями, касающиеся круги, короткие тупики |
| Маг времени | Циферблат: 12 делений на кольце, стрелки, песочные часы по вертикали | D4 для циферблата + NONE для стрелок | Кольцо-циферблат, концентрические орбиты, стрелки-цепочки к кейстоунам |

## Новый класс

1. Путь ассета: `Assets/Resources/PassiveTrees/<Class>PassiveSkillTree/<Class>PassiveSkillTree.asset`. `Tree.write` пишет полный файл сам, `.meta` создаёт Unity после `agents-unity-bridge refresh`.
2. Подключение: `Assets/Resources/Heroes/<Class>Resources/<Class>.asset` → поле `_passiveTree` (GUID из `.meta` нового дерева). Если героя нет, скажи об этом пользователю, а не создавай героя сам.
3. Тест: скопируй `Assets/Tests/EditMode/Editor/RoguePassiveTreeLayoutTests.cs` под новый путь. Он проверяет связность, взаимность связей и минимум нод. Запуск: `agents-unity-bridge run-tests --mode EditMode --filter RelicKeeper.Tests.EditMode.<Class>PassiveTreeLayoutTests`.

## Перегенерация

- `Template`, `UniqueModifiers`, `UniqueStatScalingRules` сохраняются у нод с тем же ID. ID — детерминированный хэш от класса, сектора и имени ноды в скрипте. Переименуешь ноду в скрипте — её содержимое потеряется, и скрипт выведет `WARNING`.
- Ручные правки геометрии в редакторе перегенерация затирает. Если пользователь уже двигал ноды руками, правь в редакторе или спроси, прежде чем запускать `--write`.
